# HEIC / HEIF 依赖（第十阶段 A §五–§八）——**可选安装**。
#
# 没装这份依赖，服务照样能跑：JPEG / PNG / WEBP / BMP / GIF / TIFF / SVG /
# PDF 全部不受影响，只是能力矩阵里不会出现任何 HEIC 相关的格子，
# 界面上如实说明「HEIC 支持当前不可用」。所以这个包**刻意不放进
# requirements.txt**（与 requirements-ocr.txt 同一个道理）：
#
#     pip install -r requirements-heic.txt
#
# 为什么它更不能进基础依赖 —— 除了体积，还有许可（见下）。基础依赖应该是
# 「装了就一定能用、且没有附带义务」的那一组。
#
# ---------------------------------------------------------------------------
# 许可与分发（**事实陈述，不是法律意见**）
# ---------------------------------------------------------------------------
#
# pillow-heif 的 wheel 自带 libheif，而 libheif 在这份 wheel 里链了：
#
#   * libde265  —— HEVC **解码**器
#   * libx265   —— HEVC **编码**器
#
# 上游许可（以各自项目为准，此处只记录事实）：
#
#   * libx265 是 **GPLv2**。分发链接了 libx265 的二进制会触发 GPLv2 的
#     义务；这一条对「把本服务打包分发」的场景有影响，对「自己部署自己用」
#     通常没有。
#   * HEVC 另有**专利池**（Access Advance / Via LA 等）。专利许可与
#     软件著作权许可是两件事，前者不因为代码是开源的而消失。
#
# 本仓库**没有** LICENSE / NOTICE 体系，因此这里不做任何结论性判断。
# 若要把本服务对外分发（尤其是商业分发）：
#
#     Requires project-specific legal review before commercial redistribution.
#
# 只想要解码方向（HEIC → 其它）而不想要编码方向（其它 → HEIC）：
# 能力发布只看 ``compressors.heif`` 的 ``_probe()`` 返回值，**没有配置开关**。
# 要把编码方向摘掉，需要改代码 —— 去掉 ``_probe()`` 里那段编码探测，让
# ``encode`` 恒为 ``False``；改完之后能力矩阵与界面会自动只留 HEIC 作为
# **源**的那几格（矩阵是从探测结果派生的，不是手写的）。
# 详见根目录 README.md 的「可选组件（HEIC / OCR）」一节。
#
# ---------------------------------------------------------------------------
